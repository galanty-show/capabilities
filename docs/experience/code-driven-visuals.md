# 代码写画面：先完成态，再做变化

代码让界面、文字、关系和节奏可编辑。TSX/HTML 可以精确安排每帧，也能保留给下一轮 Agent 修改；已有视频、Remotion 或 HTML 工程照其原形态制作，不能为了编辑方便强迫改成另一种格式。

## 从观众要理解的事开始

给每幕写一句可复述的结论，列对象、关系和证据。先把静止完成态画成立，再倒推揭示次序。箭头的含义要明确：顺序不自动是因果，选择不能排成串行，确认前的对象不能提前进入完成状态。

标题提出问题或结论，主体给证据，字幕跟随声音。不要把同一句长话重复在三层；先删冗字，再调字号。数据保留单位、时间窗、来源和比较口径。空卡片、漂亮框线和装饰图不能充当产品事实证据。

代码重画终端、编辑器、网页、播放窗等可精确卡拍，示意 UI 应标示意。需要证明真实操作时保留真实录屏或其他可核证据；绘制得像不代表功能已实现。片中模板数、样片数、速度和性能不能照抄历史宣传片。

## 让动作和源码都能接着改

- 新文影幕先读 `get_scene_runtime`，默认导出组件，输入类型与导入能力按真实接口。
- 每帧由 frame/fps、句时序、确定性种子及参数决定。状态不能依赖上次渲染帧；并行或跳帧导出要得到相同结果。
- 主体在 `layout.content`，字幕带交给宿主。想让用户换色就读 theme；水墨、夜景或品牌颜色固定也可以，说明支持范围。
- 动作跟实配句子或词走；纯视觉片跟固定时长与音乐网格。没有实测逐字时间不宣称逐字同步。
- 参数只暴露代码已在读取的内容。布局、运动、风格改代码，不为通用模板堆出一整套限制创作的参数。
- 多幕共享模块而只改其中一幕时，复制模块并改该幕引用，避免连带变化。

## 看过的画面才算证据

关键变化检查 start、mid、completed、precut。抽帧核对文字、关系、遮挡和边界；正常速度播放判断注意力与停留，试听判断声音。渲染成功只说明生成了文件，不能代替这些检查。

可选的慢推、压暗其他层或文字停留都有适用条件，不做审美门禁。参考 [分层慢推](techniques/slow-push-layers.md)；可复用模板见 [create-scene-template](../../skills/create-scene-template/SKILL.md)。
